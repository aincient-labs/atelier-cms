---
title: "What Atelier doesn't do"
description: "Things people ask for that Atelier can't do today — and which of them are planned"
---

Atelier builds and runs websites from a curated set of sections, with you approving every
change. Some things people reasonably ask for are outside that today. This page lists them, so
neither you nor the assistant has to guess.

## Planned, not available yet

These are on the plan. There is no date yet.

| Request | Today |
|---|---|
| **Forms**, such as a contact form | There is no form section. |
| **Raw HTML or embed code** (a widget, an iframe, a third-party form) | Sections take no HTML: the assistant arranges the named [components](/components) and never writes HTML or CSS. |
| **Visitor analytics** | Atelier doesn't count or report visitors. |

## Not something Atelier does today

| Request | Today |
|---|---|
| **Creating a new kind of section in the console** | New components come from [component packs](/component-packs) that developers build. In the console you choose which existing ones the site offers, in [Components](/components). |
| **Payments or a shop** (Shopify, Stripe, PayPal, a buy button) | Atelier has no payments or store integration. |
| **Importing from WordPress** or another CMS | There is no import tool. Content is built in the console. |
| **The assistant reading a link or browsing the web** | The assistant can't open a web address you paste. Describe what you need instead. |
| **A phone app** | There is no mobile app. The console runs in a web browser. |

## When you ask anyway

The assistant answers from these docs. If something isn't covered, it says so and points you to
the closest page instead of inventing a workaround. That is on purpose: an honest "Atelier
doesn't do that yet" is more useful than a confident guess.
